# 提交信息里的 skip-ci 标记会吞掉整条 workflow

**它不是「跳过某几步」，是「这个提交根本不创建 run」。**

## 为什么

两次实测踩到：

1. 发版工具默认在 release 提交后面加 `[skip ci]`。结果挂在 `release` 事件上的同步 workflow **一次都没跑过**——事件查询返回的总数是 0，下游分支悄悄掉队了 5 个提交。
2. 自己提 PR 时标题里带了这个标记，5 个 `pull_request` 类检查全部没被创建。把标记去掉重推，立刻全部正常触发。

受影响的事件类型：`push`（含 tag）、`release`、`pull_request`、`synchronize`。

不受影响：`pull_request_target`（关联的是基分支提交）和 `workflow_dispatch`。

**代码块、行内代码里的字面量一样算数。** 不是「出现在说明里就没事」。

## 怎么用

- 自己的 commit message / PR 标题 / PR 正文 / issue 正文里，**不要出现方括号包起来的 skip ci**。要提这件事就写「skip-ci 标记」。
- 确实要在正文里引用字面量时，用 `skip<!-- --> ci` 这种 HTML 注释写法：渲染出来是完整的，原始文本里不含该子串。
- **squash 合并时 PR 正文会进提交信息**，所以正文也得防。
- 排查「workflow 没触发」时，先 grep 提交信息，再看事件类型。

## 一条推论

**发版工具替你写的东西，也属于你的提交信息。** 默认配置里的一个后缀，可以让一条流水线安静地停摆几个月。
