# 别覆盖正在运行的 shell 脚本

**传新的 `.sh` 覆盖服务器上正在运行的脚本之前，先确认没有实例在跑。**

## 为什么

**bash 是按字节偏移增量读脚本的**，不是启动时整文件读入。文件一被替换，它的下一次读取就落到旧偏移上，读出的是新内容——于是执行串位。

真实后果，两次：

- 日志里冒出 `./secrets.env: Permission denied`——读串了，那一轮的环境变量没加载上
- `xxx.py: command not found`，而且 bash 把脚本后半段**整个重跑了一遍**，导致同一阶段一小时内跑了两轮

两次都发生在「刚改完脚本、顺手就传」的时候，而定时任务正好在跑。

## 关键区别

**Python 不受影响。** 解释器启动时把整个文件读进内存，覆盖运行中的 `.py` 是安全的。

危险的是 `.sh`。这个区别很容易被忘掉，因为平时两者看起来一样。

## 怎么用

1. **传之前先查有没有实例在跑**，有就拒绝并打印是哪个进程
2. **避开定时任务的执行点**，前后留出余量
3. 轮次跑着的时候要改，就等它结束（通常 8–14 分钟），别图快

## 一个连带的坑

`pgrep -f 'xxx\.py'` 会**匹配到自己**——自己的命令行里就含这个字符串，等待循环永远不结束。

写法要用方括号模式：`pgrep -f 'xxx[.]py'`。
