# 断言别命中你自己发的文本

**用提示词里的字符串当断言标记，会命中用户自己的消息。**

## 为什么

一个 AI 连通性探针常年绿灯，直到有人发现模型额度早就用完了。

探针的做法是：发一句 `只回答OK_<时间戳>`，然后断言页面上出现这个字符串。但这个字符串同时存在于**用户气泡**和**会话标题**里，两者都在被搜索的容器内。`.first()` 先命中了它们——于是模型一次都没回复，断言照样通过。

改成定位「只有助手才会产生的元素」之后，同一个必失败的场景立刻报红，还给出了阶段诊断。

## 怎么用

写断言前先问一句：**这个字符串是不是我自己发出去的？**

- 是 → 换成只由被测对象产生的证据：助手气泡的专用 `data-testid`、返回体里的字段、日志里的行
- 否 → 仍然确认它只可能来自被测对象

同类的「等待函数」也要查：只等容器文本稳定的函数，不校验内容。错误提示也算一次「稳定」，于是失败被当成成功。

## 一条推论

**绿灯的价值等于它的特异性。** 一个永远能通过的断言，比没有断言更糟——它会让人停止怀疑。
