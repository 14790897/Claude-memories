# 读 PR 别只看正文

**看 PR / MR 时，必须把评论和 review 一起拉下来。**

## 为什么

一次审查：只读了 PR 正文和 diff。正文里写着「本地没有测试账号，未做真实联调」，于是给了一堆怎么在本地把服务跑起来的步骤，还附带提醒某个字段可能有问题。

结果作者早在评论里贴了结论：「后端 + 真实模型联调已通过」，连证据都附上了。我的建议**既冗余又是错的**，被用户当场指出「评论是不是有」。

**正文是提交那一刻的状态，评论才是后来的进展。**

## 怎么用

```bash
gh pr view <N> --json body,comments,reviews
```

- 每次看 PR 至少带上 `comments`，有新 review 时也带 `reviews`
- **给建议、写评论、改描述之前**，先把已有评论读完
- 评论和正文冲突时，以评论为准

## 推广

同一条纪律适用于任何「有追加讨论的文档」：

- issue、MR、设计文档、周报
- 线上故障的记录页

**先读完全部记录，再开口。** 只读第一屏就下判断，十次里有三次会被后面的话推翻。
