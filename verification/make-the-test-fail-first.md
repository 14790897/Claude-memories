# 没见它红过的测试等于没测

**写完测试，把修复改回去跑一遍，确认它真的会失败。**

## 为什么

这个项目反复栽在同一个观察盲区上：**「某个功能从没被执行过」和「它能正常工作」，在外部看起来完全一样。**

两个具体例子：

**① release 构建第一次推理就崩。** debug 下一切正常，集成测试全过。但推理被一个前置门控挡着，测试环境喂不进真实输入，那条路径**从来没跑过**。直到某次环境噪声恰好越过阈值，才暴露成 SIGABRT。

**② 一个行为「有测试覆盖」，但断言写错了方向**，测试一直是绿的，而实际功能是坏的。

## 怎么用

**写完一个测试，先让它红一次。**

把修复改回原来的样子，跑测试，看它失败。再改回来，看它变绿。两次都做过，这个测试才算存在。

失败的形式也要看：断言失败、超时、异常，都算；如果它「还是绿的」，那测的不是你以为的东西。

## 更一般的判据

**覆盖率数字回答的是「这行代码被执行了吗」，不是「这个行为被验证了吗」。**

- 代码被执行：可能只是被调用了一下，返回值没人检查
- 行为被验证：有一个会在行为错误时失败的断言

## 顺带一条

用项目自己的测试框架驱动界面，不要写脚本模拟点击坐标。

坐标脚本的失败模式极其恶劣——**截图不受遮挡影响**，所以「点空了」和「点了没反应」在截图上一模一样。而框架驱动控件树，点不到就是点不到，会直接报错。
