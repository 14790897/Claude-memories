# 一致性不能证明正确性

**「两个实现的结果完全一致」只能证明迁移没引入偏差，不能证明它们是对的。**

## 为什么

一次端到端验证，比的是 ONNX 输出和框架原生输出的余弦相似度——**1.000000**，通过，还做成了诊断页上的绿色对勾。

但那两个**跑的是同一个坏掉的模型**。一致性和正确性毫无关系。

真正的错误是：模型输出本来就是**多标签、各类别独立**的概率，却被当成了需要归一化的 logits，做了一次 softmax。除以几百个值的大和之后，0.96 变成了 0.004。

后果是「置信度门控永远过不了」——整个功能从上线起**一次都没检出过任何东西**。

症状极具迷惑性：应用能跑、界面正常、就是什么都不识别。**看起来像是「真实场景太难」，很容易就此接受。**

## 怎么用

**判据先看分布形态：**

- 各类别概率之和应该大于 1（多标签）
- 多个类别可以同时超过 0.5
- 正确预测的值通常在 0.7–0.96

**然后做对照组：** 挑几个该模型一定认得出来的、训练充分的类别跑一遍。如果连最简单的那个都识别不出来，问题就不在「难」，在「坏」。

## 推广

三种验证，作用完全不同：

| 验证 | 能证明 |
|---|---|
| 两个实现一致 | 迁移没引入偏差 |
| 输出落在合理范围 | 数值没走样 |
| **有已知答案的样本能答对** | **它是对的** |

前两个便宜、能自动化，所以很容易被当成全部。第三个才是关键，而且必须用真实样本。
