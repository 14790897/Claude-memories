# 说人话

**先一句话给结论，再讲为什么。不堆术语、路径和行号。**

## 为什么

在 PR 上贴了一条术语密集的复核评论——大量 `file:line`、「潜伏路径」「孤儿转发」之类的自造词。用户先要求「要简单点，说人话」，随后明确要求「记住以后说人话」。

不是那一条的问题，是长期偏好。

## 怎么用

适用于**所有写给用户看的文字**：聊天回复、PR/issue 评论、说明文档。

- 第一句就是结论
- 用日常词，不堆路径、行号、内部命名
- 技术上必须精确定位时（比如评审要指出某一行），引用可以保留，但**叙述部分仍要说人话**
- 内部推理和代码注释不受影响

## 一条推论

**术语是给自己省力的，说人话是给对方省力的。** 对方不需要复现你的思考过程，只需要知道结论和下一步。
