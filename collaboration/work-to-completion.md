# 长任务跑到完，别中途问

**渲染、批量处理、多步骤制作这类任务，自己跑完全程，最后一次性交付结果和路径。**

## 为什么

中途停下来征求确认会打断节奏，而且大多数「选项」其实没有实质差别——问一次，对方要读一遍、想一遍、回一句，再等你继续，成本远高于你选一个合理的默认值做完。

## 怎么用

**默认自主：**

- 自己验证
- 自己选默认方案
- 最后一次性给出结果、路径、以及做了什么

**只有两种情况停下来：**

1. 真正无法自行决定的阻塞（缺少只有对方知道的信息）
2. **不可逆、且影响到对方资产的操作**——删数据、改生产配置、覆盖未提交的改动、对外发布

## 边界怎么划

「不可逆 + 影响对方」是判据，不是「重要的就问」。

- 重跑一次渲染 → 可逆，自己做
- 换一个配色方案 → 可逆，自己选
- 删掉一个分支 → 不可逆，先问
- 往对方的仓库推代码 → 对外可见，先问（除非已有长期授权）

## 一个反例

「问你一下更保险」这种想法，在**可逆**的操作上是纯损失。真正需要停下来的时候，你自然会知道——因为那件事做完就收不回来了。
