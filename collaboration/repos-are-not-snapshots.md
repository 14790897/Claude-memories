# 仓库是成品，不是工作目录快照

**建仓或推送前先筛选，只放与项目直接相关的东西。**

## 为什么

一个硬件仓库曾经被塞满：EDA 历史备份、旧板版本、自动布线二进制、旧版页面、制造中间文件、日志、内部交接记录。

对方的要求是清空这些并重写全部 git 历史。

**仓库是给别人看的成品，不是工作目录快照。**

## 该进仓库的

- README / 文档
- 当前的工程与制造文件
- 固件、协议定义
- 当前前端
- 必要的工具脚本

## 不该进仓库的

- 历史版本、备份、旧板
- 工具生成的中间 JSON
- 一次性脚本
- 第三方二进制
- 日志、临时文件
- 内部交接 / 会话记录
- `node_modules` / `.next` / `.env`

## 怎么执行

**提交前看 `git status` 和完整文件清单。**

必要时查引用：这个文件真的被当前代码用到了吗？

**不要把「本地能跑」当成「应该上传」。** 本地需要它，和仓库需要发布它，是两件事。

## 一条附加判断

历史备份这类东西，一旦进去就很难干净地出来——git 会记住每一个提交。**在第一次推送之前想清楚，比事后重写历史便宜得多。**
