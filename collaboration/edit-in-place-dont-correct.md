# 说错了改原文，不要发更正

**已经发出去的文字（issue 评论、文档、公告）发现错误时，直接编辑原文，不要追加一条「更正」。**

## 为什么

先发了一条详细评论，发现顺序写错后又追加了一条更正——对方直接说「只要一个评论」。

两条评论的问题：

- 后来的人读到的可能是**过时的那条**
- 讨论串被弄乱
- 显得反复

## 怎么用

**GitHub 评论：**

```bash
# 改
gh api -X PATCH repos/{owner}/{repo}/issues/comments/{id} -f body=...

# 如果已经发了更正跟帖，删掉它并把内容合并回原评论
gh api -X DELETE repos/{owner}/{repo}/issues/comments/{id}
```

**文档：** 改正文，不在文末追加「勘误」。

## 发之前的纪律

**一次写完再发。** 把该有的都想全：

- 环境（版本、平台）
- 症状（报错原文）
- 证据（复现步骤、日志）
- 已经试过什么
- 想要什么

## 什么时候「更正」是合理的

**当原文是被别人引用过、已经无法编辑的**（比如已发布的版本、别人转述过的内容）。

这种情况下应该：新发一条说明差异，同时**在原处能改的地方也改掉**，让单一事实源尽量收敛。
