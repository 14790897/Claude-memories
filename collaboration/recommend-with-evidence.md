# 推荐要带证据

**推荐仓库、插件或开源工具时，必须附上流行度指标，不能只列功能。**

## 要带的四项

| 指标 | 说明什么 |
|---|---|
| **star 数** | 有多少人真的用过 |
| **fork 数** | 有多少人真的改过 |
| **最近提交时间** | 还活着吗 |
| **license** | 能不能用 |

再补一句判断：**成熟 / 小众 / 很新**。

## 为什么

第一次给一份工具清单时只列了功能，对方无法判断可信度和活跃度——「存在且功能对得上」和「能放心用」是两回事。

一个几乎没人用的插件意味着：没有人验证过它，随时可能被弃养。

## 怎么取数据

```bash
gh api repos/<owner>/<repo> \
  --jq '"\(.stargazers_count) \(.forks_count) \(.pushed_at) \(.license.spdx_id)"'
```

## 阈值

- star 很少（< 20）或建仓不足一个月 → 标注「很新，谨慎」
- 星数高但**长期没提交** → 同样要提醒，可能已经跟不上新版本
- license 缺失 → 明确说「无许可证，商用有风险」

## 判断标准

**「这个工具能不能解决问题」和「该不该推荐它」是两个问题。**

前一个看功能，后一个看它有没有被足够多的人验证过。只回答前一个，等于把判断责任推给了对方。
