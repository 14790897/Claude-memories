# 碰真实账号的功能，必须真跑一次

**mock 只能证明契约对，不能证明「真的能拿到凭据并调通」。**

## 为什么

一个涉及平台登录、计费和网关凭据的功能，最初只有 mock 用例。mock 用假凭据跑通全链路——链路形状是对的，但没有一步碰过真实服务。

用户质疑后补了真实账号实测，才发现真实环境里有 mock 根本模拟不出来的差异。

## 怎么用

真实账号用例用**环境变量门控、默认跳过**，不进常规 CI：

```js
test.skip(!process.env.ACCOUNT_LIVE, '需要真实账号');
```

跑的时候由外部注入凭据，登录态和 token 落在临时目录，结束时清理。

**验证分三层，全过才叫「确定」**：

1. 协议层：直接打真实接口
2. 代码路径：真实调用走通
3. 界面层：真实账号端到端

## 一条推论

**mock 测不出「我以为的接口」和「真实的接口」之间的差距。** 那个差距只在真跑一次的时候露出来。

## 安全边界

真实凭据只经环境变量注入，**不进代码、不进 CI 配置、不写进任何文档或提交信息**。
