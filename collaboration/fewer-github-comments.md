# GitHub 上非必要不加评论

**能沉默就沉默。证据进 PR 描述或 commit message。**

## 为什么

一个 PR 的评审因为仓库规则被反复置新，我连着发了好几条带正文的 approve，还写了「复核放行（重申）」之类的说明。用户明确要求：以后非必要不要加评论。

评论是给别人看的通知，不是工作日志。

## 怎么用

- `gh pr review --approve` **默认不带正文**；被置新后重新批准也一样
- 进展、验证证据 → 更新 PR 描述，或者就地写进 commit message
- 只有机制要求的场景才评论：回复评审线程、必须说明的 dismiss 理由、触发机器人等，且**一句话说完**
- 在对话里向用户汇报不受此限

## 一条推论

**每条评论都是一次打断。** 你在 PR 上写的每一句「已完成」，都在给所有关注者推送一次通知，而他们并不需要知道。
