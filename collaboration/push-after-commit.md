# 提交之后立刻推送

**做完 `git commit` 之后必须立刻 `git push`，不要等对方开口。**

## 为什么

一次提交完就停下来汇报，用户随后自己把提交推了上去，并明确指示「记住提交之后必须推送」。此前多次提交也都是用户自己推的。后来又补了一句「自动推送 git」——意思是不靠记性，要在 git 层面自动化。

## 怎么用

- 在同一条命令链里完成 `git add` → `git commit` → `git push`，不要分轮次等确认
- 推送失败时，用 `git log origin/<branch>..HEAD` 说明还剩什么没上去，别默默跳过
- 如果某个仓库装了 post-commit 钩子做兜底，仍然保留显式 push——钩子会被停用，命令不会

## 一个容易忽略的点

`.git/hooks/` **不随仓库分发**，所以钩子只存在于装了它的那台机器、那个仓库。换仓库、换机器都要重新考虑这件事。凡是「以为自动化兜住了」的地方，都要确认兜底范围到底是哪几个仓库。
