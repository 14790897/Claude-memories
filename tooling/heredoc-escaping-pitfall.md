# 别用 heredoc 喂补丁脚本

**路径里的反斜杠会经过两层解析，出错还是静默的。**

## 为什么

在 Windows + Git Bash 下用 `python - <<'EOF' … EOF` 做字符串替换，反复踩坑：

1. **两层解析**：bash 的 heredoc 一层，Python 字符串字面量一层。`C:\Users\...` 在非 raw 字符串里会触发 `truncated \UXXXXXXXX escape`
2. **静默失效**：要替换的串和文件实际内容差一个反斜杠，`replace` 什么也不做，也不报错。看起来「补丁打完了」，实际上文件一个字节没变

## 怎么用

- **改文件一律用编辑工具**：所见即所得，匹配失败会报错
- heredoc 只用来跑**不含路径转义**的纯执行命令
- 万一必须在脚本里出现 Windows 路径，用 raw 字符串，并对 `replace` 的结果做断言

## 一条推论

**静默失败比报错贵。** 报错告诉你哪里错了；静默失败让你以为已经做完了，然后基于错误的前提继续往下走。
