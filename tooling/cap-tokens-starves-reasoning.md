# 给推理模型设 max_tokens 会让它「拒绝回答」

**调用带思考的模型时不要传 `max_tokens`；需要结构化输出就在提示词里要求 JSON。**

## 为什么

推理模型的**思考内容与正文共享同一个 token 预算**。

设一个小的上限，思考会把预算吃满，正文就是空的（`finish_reason=length`）。表现是**「模型拒绝回答」的假象**——实测：某类标题在 `max_tokens=60` 下思考用了 116 token、正文 0 字；去掉限制后正常返回 JSON。

模型输出完 JSON 之后会自然停止（`finish=stop`），不需要人为封顶。

## 结构化输出

**在提示词里直接要求返回 JSON，代码用 `json.loads` 解析。**

不要用正则去解析自由文本——它会把截断的碎片（比如「评级」两个字）当成合法结果存进库，而这类垃圾数据**不会被重扫修复**，会一直留在那里。

## 怎么用

```python
# 提示词
"只输出一行 JSON，不要输出其他内容。示例：{\"label\": \"...\", \"score\": 0.0}"

# 解析：主路径 + 容错链
try:
    return json.loads(text)
except json.JSONDecodeError:
    pass
# 再试：JSON 嵌在文本里 → 旧式文本格式 → 关键词兜底
```

## 一条更宽的判断

**「省 token」在推理模型上经常是负优化。** 省下的那点输出，换来的是一整批静默失败的数据。

真要控成本，控的是**调用次数和频率**，不是单次输出长度。
