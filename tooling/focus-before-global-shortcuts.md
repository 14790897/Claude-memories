# 发快捷键之前先确保焦点在目标窗口

**桌面自动化里，系统级快捷键会落到当前前台窗口——而那很可能不是你以为的那个窗口。**

## 为什么

一次浏览器自动化的操作中，我用快捷键 `Ctrl+W`。但目标浏览器并没有获得焦点，于是被关掉的是**AI 客户端自己的对话标签**。同一轮里反复发生，事后只能靠历史记录找回。

风险最高的一组：`Ctrl+W`、`Ctrl+T`、`Ctrl+Shift+A`、`Alt+F4`——都是会改变窗口结构的。

## 怎么用

**能点元素就别用快捷键。** 页面里点得到的按钮和链接，按文字位置点，不要用快捷键绕。

**非用快捷键不可时，先点一下目标窗口里无害的空白点**——工具栏空白、内容区留白——再发按键。

**判定焦点在哪儿**：发按键之前先读当前前台窗口的标题或进程名，确认就是目标。不确定就点，不按。

## 一条更宽的边界

凡是通过 `SendInput` 级 API 发出去的输入，都是**系统级**的，不认浏览器上下文，只认前台窗口。任何「我以为它在后台」的假设都成立不了。
