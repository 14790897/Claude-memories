# 能写成 if 就别写提示词

**AI 只用在「真的需要理解自由文本」的地方。**

## 为什么

原来有个分类任务，因为需求文档里提过「用大模型」，就顺理成章地调了模型。

但实测下来，几类角色里有信息量的那两类，本来就是**确定性判据**：

- 一类看合约名里的关键词
- 一类看「与已知地址的往来占比」——纯算术

用模型等于**在自己已经算出来的特征上再做一次映射**：多花一笔钱，还多一层不可复核的黑箱。

全套规则化之后：一致率 88%，而且规则**纠正了模型判错**的案例。边际成本从「每轮几百到几千次调用」降到 **0**。

## 怎么用

**新增任何「分类 / 判定」需求，先用一句话写下判据。**

- 判据能写成 `if` → 走规则
- 判据真的需要「理解含糊的自然语言」→ 才调模型

**真要调模型，先估「每轮 × 频率」的总量**，不是单次价格。定时任务上的调用是持续开销：一次跑几百个看着便宜，每小时一轮就是每天几千次。

## 已经花过钱的模型产出别丢

留作**基线**，用规则跑一遍比对一致率。一致的地方说明规则够用；不一致的地方正好用来校准阈值——实际有几次就是按模型标签的分位数定的规则阈值。

## 一个分工问题

**「这个需求要不要用 AI」是产品侧决策，先问。**

**「已经确定要做的判定，用什么方式实现」是技术决策，自己定成规则。**

两者经常被混在一起，结果是把技术选择包装成了产品需求。
