# 读图失败时别猜

**图片读取工具返回「不支持的格式」时，换一条通道看图，不要靠文件名猜内容。**

## 为什么

某些环境下，图片读取工具对一部分 JPEG / PNG 会返回 `[Unsupported Image]`——这不是图片本身坏了，是渲染层的问题。

放弃读取、或者根据文件名推断图里是什么，会导致后续所有判断建立在猜测上。

## 怎么用

**准备一条备用视觉通道。** 可以是另一个 MCP 的识图工具，也可以是任何能返回图像描述的服务。

**批量选图时先拼总览图。** 把候选图缩略拼成一张 contact sheet，先整体看一遍定位方向，再对少数几张逐张细看。这比一张张硬读省得多，也更容易发现「看起来像但其实不是」。

**注意单次读取的图片数量上限。** 多图批次直接走备用通道，不要指望一次全读。

## 一条通用原则

工具失败时说「读不了」，比编一个描述强。但如果这个失败是稳定可复现的、且有替代通路，那就该走替代通路，而不是每次都停在这里问用户。

区别在于：**「这个文件读不了」**是事实；**「我看过了，图里是一个人」**——如果没真看到，就是编的。
