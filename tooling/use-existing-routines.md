# 定时任务用现有调度器，别另起一套

**需要「每天 / 每几小时自动做一次」的任务，优先复用已有的调度机制，不要新建系统级计划任务。**

## 为什么

一次做登录保活，我在 Windows 上注册了一个计划任务。用户当场否决：「不要 Windows 计划任务，不是有 routine 吗」。

已有的 routine 是他自己维护的统一入口。多一套调度器意味着：

- 行为来源不可见——同一个动作有两个出处
- 日志分散在两处，排查时得同时翻
- 停用、修改、审计都要记住两套路径

## 怎么用

**先查有没有现成的。** 列出已有定时任务，看能不能改它的定义。

**能改就不新建。** 改 cron、改提示词、改执行范围，都比重开一套划算。

**只有在明确要求「不依赖当前应用也要跑」时**，才考虑系统级调度。

**routine 的定义要写清楚**：

- 失败判据（什么情况算这次跑失败了）
- 输出格式（成功了说什么，失败了说什么）
- 边界（比如「只关自己开的页签」）

## 推广

「已有的统一入口」比「更合适的工具」更重要。

一套分散的调度器，三个月后就没人说得清某个定时行为到底是谁在跑、为什么跑。集中在一处，哪怕那一处的表达力差一点，也好过分散。
