# 只碰自己开的标签页

**浏览器自动化只允许操作本次自己新开的标签页。绝不关闭、移动、切换用户原有的窗口和标签页。**

## 为什么

一次登录保活任务里，我用脚本对主浏览器的默认 profile 反复 `--new-window` 再 `WM_CLOSE`。结果主浏览器里大量标签页消失，用户强烈反对——「你不要动我主浏览器的 tab 啊」——最后只能去历史记录里手动恢复。

那是他日常使用的浏览器，开着几十个正在用的页面。

## 怎么用

**收尾时只关本轮记录里自己创建的 tab id。** 其余的，一个都不碰。

**需要新窗口时先确认。** 默认答案是不允许。确实需要的，先问。

**需要判断登录态或刷新页面时**，走已有的自动化通道开新标签，不要从外部启动浏览器进程。

**拿不准就什么都不关。** 在报告里写明「未关闭任何窗口」。

## 推广

这条不是浏览器专属的。「用户正在使用的界面」和「我创建的工作环境」是两个域，边界要清楚：

- 用户打开的终端、编辑器、文档——只读不写，不关闭
- 自己起的进程、自己建的临时文件——用完自己收拾

越界一次，用户就要花时间去恢复，而且会开始不信任自动化。
