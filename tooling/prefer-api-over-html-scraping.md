# 抓内容先用 API，别一上来扒 HTML

**抓任何站点的内容时，先花 30 秒找 API，再考虑抓 HTML。**

## 为什么

一次抓某阅读平台的书籍正文，我一直在试网页——那是个 SPA，正文是空的。一句「那你直接抓 API 呢」点破了：平台的读接口直接返回 JSON 正文，无页头页脚、无编码问题、一次一章。

对比之下，HTML 抓取要处理分页、导航杂质、编码（gbk / gb18030）、PUA 私用区乱码，还有清理时误删的风险。之前抓八部剧本花的力气，大半都消耗在 HTML 清理这条链路上，而不是内容本身。

## 怎么用

**先探 API，四步：**

1. 在网页源码里搜 `api`、`/api/`、`fetch(`、`__NUXT__`、`__INITIAL_STATE__`
2. 试常见路径：`/api/{resource}`、`?format=json`、REST 风格端点
3. 按「列表页 → 详情页 → 内容页」的 XHR 顺序推断端点
4. 拿不到再退回 HTML

**有些站确实没有 API**——静态站、古籍站、个人站。这时候 HTML 抓取是唯一选择，但要把编码和清理规则先想清楚。

## 判断标准

如果目标数据是**结构化的**（正文、列表、字段），一定有接口，哪怕是内部接口。

如果目标是**呈现效果**（排版、图片位置、分栏），那才需要 HTML。
