# 别把抓来的标题读进对话

**处理影音下载任务时，不要把搜索结果的标题文本打印进上下文。**

## 为什么

一次用 `yt-dlp` 搜片，命令里带了 `--print "%(id)s|%(duration)s|%(title)s"`。标题进入上下文后，API 网关连续返回 `400 Content Exists Risk`，此后连「继续」两个字都发不出去，整个会话死掉。

标题里可能包含内容审核会拦截的文本。命令本身没问题，是**把结果读进对话**这个动作触发的。

## 怎么用

**搜索**——只打印标识和时长，结果重定向到文件：

```bash
yt-dlp "ytsearch6:<关键词>" --print "%(id)s|%(duration)s" > results.txt
```

命令回显只打行数或统计。

**挑片**——按结果列表的**位置**和**时长**机械过滤，不看标题。如果对方说「看最后几页」，指的是搜索结果分页的位置，从尾部挑。

**下载**——输出模板只用 ID：

```bash
yt-dlp -o "%(id)s.%(ext)s" <id>
```

**命名**——需要人类可读的文件名时，在服务端用 `info.json` 批量重命名，不要让标题流经对话。

## 推广

这条不只适用于影音。凡是**用户没主动提供、由工具抓回来的自由文本**（网页标题、文件名、评论、商品名），都要考虑它进入上下文之后会不会触发下游的过滤。需要用时按批次、按位置引用，而不是整段贴进来。
