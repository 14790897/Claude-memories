# beforeAll 是每个 worker 一次，不是每个文件一次

**一条用例失败导致 worker 重启，剩下的用例会拿到一个全新的环境。**

## 为什么

一个 spec 里第一条用例建了数据，第二条断言「有数据但搜不到」的空态文案。CI 上第二条稳定失败，三次重试都挂在同一行。

原因是第一条用例失败后 worker 重启，剩余用例被排到新 worker，`beforeAll` 重新跑了一遍启动流程——**新实例的存储目录是全新的**，前面建的数据一条都不在。于是代码走进了另一个分支，断言自然找不到元素。

`beforeAll` 也不是「整个文件一次」，是每个 worker 一次。并发跑、失败重启，都会让它多跑几遍。

## 怎么用

- 需要数据的用例**自己幂等补齐**：函数写成「按目标条数补齐，已有的直接复用」，而不是「查到空就建」
- 不要在 `beforeAll` 里建数据，然后假设每条用例都能看到
- 排查时先确认「这条用例拿到的环境，是它以为的那个吗」

## 一条推论

**测试之间的隐式依赖，在单进程顺序执行时永远看不出来。** 它只在并发和重试时现形——也就是恰好在 CI 上。
