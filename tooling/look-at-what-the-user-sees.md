# 验的是「用户看到的」，不是「数据在不在」

**任何影响界面的改动，改完必须打开页面走一遍，读 DOM 确认。**

## 为什么

一次数据接入：后端确实返回了带品牌名的字段，`curl` 200、JSON 字段齐全——**但界面上一个都看不到**。

因为后端根本没 JOIN 那张表，前端也只渲染原来那六类角色。

`curl` 返回 200 完全掩盖了「用户看到的是错的」。查了半天数据，最后发现是界面根本没接上。

## 怎么用

**任何影响界面的改动**（前端、接口字段、新数据源、调度状态）改完之后：

1. 打开页面
2. **强刷**，别看到缓存的旧包（先确认构建产物里确实有新字段）
3. 走真实的导航路径进去
4. **读 DOM 文本**确认

**优先读 DOM 而不是只截图**：截图在窗口最小化时会超时，而且看不清细节；`element.innerText` 能精确拿到用户看到的字符串。截图留给像素级确认。

## 前端必查四项

- 字段名前后端对得上
- 渲染分支走对（有值走一条、空值走另一条）
- 长文本不撑破单元格
- 空值不显示成 `—` / `undefined` / `null`

## 图纸类也一样

出图（原理图、PCB、3D 预览）交付前必须**截图并放大逐块检查文字**。

「整页 fit 视图」不算验收——网表正确、ERC/DRC 全过，也不代表别人能看清你的图。

检查项：引脚名、位号、值、网络标签是否清晰、有无重叠。整页文字太小就增大字号、减少留白或拆页，**不要用「缩放后能看」当借口**。
